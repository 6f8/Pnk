# كاشف — تحليل بانك الآيفون وتشخيص أعطاله (C# / WinForms)

افتح ملف **panic-full** من الآيفون أو الصق نصه (حتى المنسوخ من صورة)، فيظهر:
**التشخيص**، و**الأسباب مرتبة** من الأرجح إلى الأبعد، و**خطوات الفحص**، و**الأدلة من السجل نفسه** (أي سطر بُني عليه كل استنتاج).

مبني بنفس ترتيب وأسلوب كود **توافق (YAM)**: نفس الطبقات (`Core` / `UiKit` / `Forms`)، نفس النافذة الرئيسية بالقائمة الجانبية والتبويبات، نفس شاشة التعريفات العامة (`CrudForm` + `Defs`)، ونفس قاعدة البيانات (SQLite بملف واحد).

## التشغيل
1. ثبّت **Visual Studio 2022** (حمولة ".NET desktop development") أو **.NET 8 SDK**.
2. افتح `Kashif.csproj` — تُنزَّل حزمة `Microsoft.Data.Sqlite` تلقائيًا.
3. شغّل بـ F5، أو من الطرفية: `dotnet run`
4. نسخة تنفيذية مستقلة: `dotnet publish -c Release -r win-x64 --self-contained -p:PublishSingleFile=true`
5. الدخول الأول: **admin / admin** — ثم شاشة ترحيب لبيانات المحل وكلمة مرور جديدة.

بيانات المحل: `%LOCALAPPDATA%\Kashif\kashif.db` — وسجل الأخطاء في `errors.log` بجانبها.

يمكن فتح ملف ‎`.ips`‎ مباشرة بالبرنامج («فتح باستخدام» أو سحبه إلى أيقونة `Kashif.exe`).

## من أين يأتي ملف البانك؟
على الآيفون: **الإعدادات ← الخصوصية والأمان ← التحليلات والتحسينات ← بيانات التحليلات** ← الملف الذي يبدأ اسمه بـ `panic-full`.
افتحه ثم شاركه (AirDrop / الملفات / واتساب) أو انسخ نصه كاملًا والصقه في البرنامج.

## الشاشات
| الشاشة | ماذا تفعل |
|---|---|
| **الرئيسية** | بدء فحص (فتح ملفات أو لصق أو سحب الملفات)، مؤشرات، القطع الأكثر تسببًا بالبانك، آخر الفحوصات |
| **تحليل البانك** (F2) | عدة سجلات معًا، نص السجل (قابل للتعديل)، «ما حدث للجهاز» (سوائل، بطارية/فلاتة/شاشة مستبدلة، سقوط)، ثم الخلاصة وتبويبات: الأسباب، الخطوات، الأدلة، التقرير، الزبون والحفظ، فحوصات سابقة لنفس الجهاز |
| **سجل الفحوصات** | كل فحص محفوظ مع نص سجلاته الأصلي — يُعاد تحليله عند الفتح بأحدث قاعدة معرفة |
| **دليل رموز البانك** | معنى كل رمز يعرفه البرنامج (Prs0، TG0B، thermalmonitord، SMC ...) والقطع المرتبطة به حسب جيل الجهاز |
| **خبرة المحل** | أضف ما تأكدت منه بنفسك: نص يظهر في السجل ← القطعة التي كانت السبب. بدرجة «مؤكد» يصبح هو الأرجح في التحليلات القادمة |
| **التقارير** | الأعطال الأكثر تكرارًا، حسب نوع البانك، حسب الجهاز، سجل العمليات — طباعة وExcel |

اختصارات شاشة التحليل: `Ctrl+O` فتح ملفات — `Ctrl+V` لصق — `F9` تحليل النص — `Ctrl+S` حفظ — `Ctrl+P` طباعة التقرير.

## كيف يحلّل؟
المحرك في `Core/Panic/` مستقل عن الواجهة وقاعدة البيانات:

- **`PanicLog.cs` — القراءة:** الملف الأصلي (سطر رأس JSON + جسم JSON) يُقرأ كـ JSON. النص المنسوخ أو الناقص أو المأخوذ من صورة يُقرأ **بالاستخراج المرن**: أقواس ناقصة، أسطر مكسورة داخل القيم، مسافات داخل أسماء المفاتيح (`panic ProcessingFlags`)، و`\n` مكتوبة حرفيًا. عدة سجلات ملصوقة معًا تُقسَّم عند كل `bug_type`.
- **`AppleDevices.cs` — الجهاز:** اسم الجهاز من `product` (مثل `iPhone12,1` ← iPhone 11)، وإن غاب فمن رمز البوردة في سطر SMC (مثل `target/d94` ← iPhone 16 Pro Max)، واسم المعالج من سطر النواة (`T8030` ← A13). الرمز غير المعروف يظهر كما هو ولا يُخمَّن.
- **`PanicAnalyzer.cs` — الحقائق:** سطر الانهيار، **الحساسات المفقودة** (`Missing sensor(s)`)، **الخدمة المتوقفة** ومدة الانتظار (196 ثانية ← «يعيد التشغيل كل 3 دقائق»)، و**مفاتيح SMC** المفكوكة من رسائل Mailbox (`0x5447304200006013` ← `TG0B` = حرارة البطارية).
- **`PanicKnowledge.cs` — قاعدة المعرفة:** رموز الحساسات وأماكنها حسب جيل الجهاز، مفاتيح SMC، خدمات النظام، وتواقيع أنواع البانك (AOP، SEP، NAND، DCP، I2C، الواي فاي، البيسباند، الكاميرا، البصمة، آيسي الشحن، GPU، PMU، النواة).
- **الترتيب:** لكل سبب درجة للترتيب (ليست نسبة مئوية): «الأرجح» فقط إذا تقدّم بوضوح، ثم «مرجّح» و«محتمل» و«احتمال بعيد». **درجة الثقة** (عالية / متوسطة / منخفضة) تقول كم يعتمد التشخيص على دليل مباشر.
- **عدة سجلات لنفس الجهاز** (بمفتاح التقارير `crashReporterKey`): تكرار نفس الحساس يرفع الثقة، واختلاف أنواع البانك يخفضها ويرجّح سببًا عامًا (بطارية، طاقة، تأكسد، بوردة، نظام). السجلات من أجهزة مختلفة لا تُجمع ويظهر تحذير.

> **حدود التشخيص:** سجل البانك يدل على **المسار** الذي انقطع (حساس، خط، معالج مساعد)، والتأكيد النهائي دائمًا بالفحص العملي: فصل القطعة المشتبه بها أو تركيب قطعة سليمة. لهذا تظهر مع كل تشخيص خطوات الفحص بالترتيب.

## الاختبارات
`Kashif.Tests/` يشغّل المحرك على سجلات حقيقية (منسوخة من صور) وسجلات ‎`.ips`‎ سليمة وحالات حدّية:

```
dotnet run --project Kashif.Tests
```

السجلات في `Kashif.Tests/Samples/`: بانك SMC لـ iPhone 16 Pro Max، بانك `Prs0` لـ iPhone 11، `mic1` لـ iPhone X، خطأ نواة، وكراش تطبيق (`bug_type 309` — ليس بانك).
