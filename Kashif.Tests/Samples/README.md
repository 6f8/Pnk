# سجلات الاختبار

كل ملف بانك هنا يُحلَّل في الاختبارات، ويُقارن بملف بنفس الاسم مع `.expected`:

```
device=iPhone 11
kind=حساس مفقود
top=ChargingFlex
confidence=عالية
```

- `top`: مفتاح القطعة من `Parts` في الكود (ChargingFlex، Battery، BatteryConn، Board، Ios ...) — **للحالات الحقيقية من المحل اكتب القطعة التي أصلحت الجهاز فعلًا**. فارغ = لا يوجد سبب.
- الحقول غير المكتوبة لا تُفحص.

لإضافة حالة حقيقية: ضع ملف `panic-full-....ips` هنا، واكتب بجانبه `panic-full-....ips.expected` بالقطعة التي أصلحته، ثم شغّل الاختبارات.
إذا فشل الاختبار فالبرنامج أخطأ في هذه الحالة — وهذا بالضبط ما نريد معرفته.

تقارير كل سجل محفوظة في `../Snapshots/`: أي تعديل على قاعدة المعرفة يغيّر ترتيب الأسباب يظهر كفشل.
بعد مراجعة التغيير وقبوله: `KASHIF_UPDATE_SNAPSHOTS=1 dotnet run --project Kashif.Tests`

## حالات حقيقية مؤكدة

- `smc_bsc_d64_screen_sensor.ips` — iPhone 13 Pro Max، ‏`SMC BSC failure` مع إعادة تشغيل بعد حوالي 3 دقائق من كل إقلاع. استمر البانك بعد تبديل البطارية بأصلية جديدة، وتوقف بعد تبديل **حساس الشاشة (القرب والإضاءة)**. الملف مختصر: نص البانك وحقول الرأس فقط، بدون قائمة العمليات (لا يستخدمها التحليل).
